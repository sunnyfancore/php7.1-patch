# 两个 CVE 的源码复核记录（r2）

范围为 CVE-2026-109618 / CVE-2026-109619 的 EOL 最小缓解回移植。参考 PHP 7.4 官方提交 [712e60f9](https://github.com/php/php-src/commit/712e60f9edfd03f0960fc4fc3c2c375f42b90aa2)，逐项核对 PHP 7.1 的对应结构和调用路径。宝塔版本号和额外文件未作为补丁内容导入。

| 路径 | 复核与处理 | 验证 |
| --- | --- | --- |
| zend_alloc / multiply / strtod / hash | OOM 和相关整数溢出直接退出进程，避开请求清理；r2 补上巨大分配对齐回绕检查 | CLI OOM、乘法溢出、Zend/系统分配器 SIZE_MAX、请求启动 OOM |
| shutdown_executor | 异常处理器、异常指针和对象存储复位；r2 为三个栈调用带正确元素尺寸的 zend_stack_init | 连续请求、处理器析构 fatal 后在初始化前触发 INI 警告 |
| VM concat | 上限检查覆盖专用 handler；r2 删除重复检查 | 从 def 重新生成并比较 execute.h（仅忽略原版已有空白行）、上游拼接回归 |
| php_variables | 7.1 的 table mask 与 7.4 不同，最小表保留 2 桶，维持 Bucket 对齐 | 嵌套变量及 300 项表扩容 |
| SAPI/main | 请求释放后将 auth/content type/current user、HTTP globals、modules_activated 清零 | 同 worker 连续请求 |
| session/rfc1867 | 强制禁用上传进度；限制 multipart 段数、只保留使用的头并忽略重复头，长度使用 size_t | 实际 FPM/Apache 上传、重复头、超限请求 |
| RPM/安装器 | 纯 FPM 不要求 CLI；精确校验源码提交与 RPM；比较升级前后扩展；保留配置 | r1→r2 升级及配置校验 |
| 服务控制 | 升级前捕获活动状态，配置检查和重启失败均中止；旧包脚本自动重启行为已记录 | service double 校验失败退出，实际进程/请求另行测试 |
| Apache RPM 依赖 | 为 mod_php71w 子包显式声明 httpd-mmn、httpd 和同版本 common 依赖 | 干净容器安装、r1 升级及 HTTP 请求 |
| Actions 发布门禁 | 显式使用 bash + pipefail，测试失败不能被 tee 覆盖；PHPT 在可写临时目录运行 | 非零退出阻断后续发布 |
| Actions 重用 | 默认拒绝所有影响编译/RPM 的文件变化，包括 sapi、根构建文件及 spec | 重用检查器，源码更改必须重编译 |

测试探针仅在 CI 使用，不包含在发布 RPM 中。额外运行原版字符串、输入变量解析和拼接的定向 PHPT；完整旧版 PHP 测试套件没有运行；集成测试证明列出的路径与场景，不能证明所有扩展和所有异常路径都不存在漏洞。此项目不宣称这是官方维护版本或完整安全认证。

## 提取来源

对官方 7.1.33 与宝塔 7.1.34 归档按相对路径逐文件比较，19 个修改文件中排除 configure/configure.in 的版本号差异，得到 17 个源码补丁文件；另外 4 个宝塔新增文件未导入。这个数量是差异提取结果，不等于安全完整性证明。

官方归档 SHA256：`0055f368ffefe51d5a4483755bd17475e88e74302c08b727952831c5b2682ea2`。宝塔归档 SHA256：`e8ce9c7ec2bd7318872a2edeb52037ac15bf4732bc4a6edce982c7e8e78c8ff8`。
